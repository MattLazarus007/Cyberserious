# Tabletop exercise, 9 November 2026

This was a discussion, not a live drill. No control was switched and no metric was measured. The point was to test the decisions, not the tools.

## Scenario

At 09:00 the security page shows a burst of failed sign-ins from one address. A minute later the same address signs in with a valid password and a stolen one-time code. The session opens two cases, then exports a register. The export reaches the row cap.

## Participants

The incident lead, the information officer, the regulator engineer and the security reviewer. Four roles, one room.

## Decisions

1. Lock the regulator through the documented restart path. The incident lead owns the call.
2. Revoke every session and rotate the internal token. The engineer owns the action.
3. Keep the organisation portal running, because it holds its own session store. The engineer confirms the separation.
4. Start the section 22 notice only after the scope is confirmed. The information officer owns the wording and the timing.
5. Check the anchor and copy the chain before any repair. The reviewer owns the evidence.

## Gaps found

- The trip wire counts one address. A distributed burst does not trip it.
- Keycloak realm MFA is not enrolled. The app code is the only second step.
- The daily anchor is a local HMAC file. It is not an external timestamp.
- The organisation portal has no trip wire. It relies on the request guard and the rate limiter.
- There is no on-call rota. The owner is the only operator.

## Follow-up

1. Run the live trip drill and record its timings.
2. Record the Keycloak MFA decision in an ADR.
3. Add the distributed-burst limit to the control matrix.
