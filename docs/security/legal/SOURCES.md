# Legal sources for the compliance matrix

| Instrument | Provisions used | Source | Status |
|---|---|---|---|
| POPIA 4 of 2013 | s14, s17, s18, s19, s22 | `legal/popia-extracts.txt`, taken from thepopiact.co.za which states it cross-checks against the justice.gov.za official PDF | Read and quoted |
| ECTA 25 of 2002 | s13, s50, s51, s52 to s55, s95 | `legal/ecta-extracts.txt`, taken from the gazette copy a25-02.pdf on gov.za | Read and quoted |
| PCI DSS | scope test only | `legal/pci-scope.txt` | Scope test run, not applicable |

## Rules for using these sources

1. Quote the extract file. Do not paraphrase a clause from memory.
2. The ECTA copy is a scan. The conversion carries character damage. Quote
   only the fragments in the extract file, and check a fragment against the
   PDF page before a report uses it.
3. Name the section number in every claim. A claim that says "POPIA requires"
   without a section is not usable.
4. Where the text gives a discretion to a Minister or the Regulator, say so.
   A discretion is not an obligation on this system.

## What these instruments do not cover here

- The Information Regulator's own section 22 form and guideline are not
  reproduced in this repository. The system records a submission, not a filing
  on the Regulator's portal. That is a stated limit.
- No ministerial notice under ECTA s53 declares this database critical. The
  chapter therefore places no obligation on the system on this evidence.
- No code of conduct under POPIA s60 has been issued for this sector in a form
  that binds the project.
